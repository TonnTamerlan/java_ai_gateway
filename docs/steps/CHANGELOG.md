- 2026-05-18 — Step 8: calc-service multipart upload + Kafka publish/echo loop (commit `184db71`, entry backfilled 2026-05-19). `POST /api/summarize` becomes a multipart endpoint accepting up to 10 `.txt` files + one batch prompt. `KafkaRequestPublisher` (gated on `spring.kafka.bootstrap-servers`) replaces the no-op `RequestPublisher` seam and publishes vendor-pure `SummarizationRequestMessage` envelopes (added to `shared-contracts`) to the `summarization-requests` topic. A local `SummarizationEchoConsumer` closes the loop in-service — marks files DONE and rolls job status up — pending the real AI side in Step 9. Boot 4 gotcha: `KafkaAutoConfiguration` did not auto-create a `KafkaAdmin` bean alongside user-defined producer/consumer factories, so `KafkaConfig` wires one explicitly to guarantee topic creation. Frontend gets `FileSummarizationPanel` (AntD `Upload.Dragger` + `TextArea` + polling status table).
- 2026-05-19 — Step 9: real OpenAI Batch API wired through ai-gateway. `BatchProvider` + `BatchSubmission`/`BatchHandle`/`BatchStatus`/`BatchResult` envelopes added to `shared-contracts` (per ADR D3). `OpenAiBatchProvider` uses `com.openai:openai-java` 4.36 (Files + Batches). ai-gateway/core gains a Kafka batch listener on `summarization-requests` (max-poll-records=5, fetch-min-bytes=5000, fetch-max-wait=180s — approximating "5 OR ~3 min"), pins items to `ModelTier.FAST`, and persists `ai.batch_correlations` (Flyway V1). A `@Scheduled` `BatchPoller` polls open batches, fetches JSONL output, and emits `SummarizationResponseMessage` to a new `summarization-responses` topic. calc-service drops `SummarizationEchoConsumer` and adopts `SummarizationResponseConsumer` that calls existing idempotent `markDone`/`markFailed` paths. WebFlux + JDBC coexistence required pinning `spring.main.web-application-type: reactive`.
- 2026-05-19 — Step 10 slice A: global files table in the frontend. calc-service: Flyway V3 adds `file_name TEXT NOT NULL DEFAULT ''`; `SummarizeController` now threads `upload.getOriginalFilename()` through `FileInput` into the row. New `FilesRepository.search(status, nameSubstring, Pageable)` custom fragment uses `JdbcAggregateTemplate` so `Pageable.getSort()` actually drives the SQL (`@Query` + `Pageable` won't — Spring Data JDBC doesn't auto-inject `ORDER BY`). New `GET /summarize/files` returns `Page<FileSummaryView>` (drops `originalText`); sort field whitelist (`fileName`/`status`/`createdAt`/`updatedAt`) → 400 otherwise; `spring.data.web.pageable.max-page-size=100`. Frontend: extracted `status.tsx` shared util; new `FilesTable.tsx` does server-side paging/sort/status filter/debounced (300 ms) case-insensitive name search, expandable rows showing prompt + summary, and a per-row info-icon `Popover` with model + prompt/completion tokens. End-to-end verified live in Chrome: search filters to matching rows, expand reveals prompt, hover popover renders stats.
- 2026-05-19 — Step 10 slice A.2: files table UX polish + soft delete. Flyway `V4` adds `deleted_at TIMESTAMPTZ NULL` + partial index `(created_at DESC) WHERE deleted_at IS NULL`. Renamed `findByJobIdOrderByCreatedAt` → `findByJobIdAndDeletedAtIsNullOrderByCreatedAt` (used by job-detail view + Kafka roll-up); `search` criteria now pin `deletedAt IS NULL`. New `DELETE /summarize/files` accepts `{ids:[...]}` (bean-validated `@NotEmpty @Size(max=100)`), returns `{deleted:N}`; new `MethodArgumentNotValidException` handler preserves the `{"error": "..."}` shape. `softDelete` is a `@Modifying @Query` (`UPDATE ... SET deleted_at WHERE id IN (:ids) AND deleted_at IS NULL`) — idempotent re-delete returns 0. Frontend: replaced the dedicated stats column with a row-level `Popover` mounted via `components.body.row` (100 ms hover delay), turned on `expandRowByClick: true`, added `rowSelection` + a `Popconfirm`-gated Delete button that refetches the page after each delete and steps back if the current page empties. End-to-end verified live in Chrome and via curl: empty `ids` → 400 `{"error":"ids must not be empty"}`, valid → 200 `{"deleted":1}`, re-delete returns `{"deleted":0}`, deleted rows disappear from `GET /summarize/files`.
